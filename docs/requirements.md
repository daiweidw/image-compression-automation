# 本地图片压缩管理工具需求文档

## 1. 文档信息

- 文档版本：v3.1
- 更新日期：2026-08-14
- 当前目标：P0 会话式待压缩工作台
- 首要平台：Apple Silicon macOS

## 2. 改版目标

旧流程要求先找到并设置“原图目录”，再设置结果目录，主页面还以固定的“原目录 -> 新目录”关系展示图片。这个流程准备步骤多，也不适合从多个位置临时收集图片。

新版把主列表定义为“本次待压缩列表”：用户先把想处理的图片加入列表，整理后开始压缩。原图来源和结果保存位置彼此独立，不再要求配置原图根目录。

## 3. 需求优先级

### 3.1 P0：当前必须交付

#### 图片加入

- 主页面支持把一个或多个图片文件直接拖入。
- 主页面提供明显的“扫描文件夹”入口，使用系统目录选择器选择任意目录。
- 扫描支持递归子目录；当前设置中的递归选项作为扫描默认值。
- 拖入与扫描得到的图片追加到同一待压缩列表，而不是覆盖现有内容。
- 同一路径重复加入时去重，不制造重复压缩项。
- 支持 PNG、JPEG/JPG、WebP 和 AVIF；隐藏文件、符号链接及不支持的文件不加入列表。

#### 扫描状态

- 扫描期间显示正在扫描、已发现数量、已处理数量和警告数量。
- 扫描期间提供可点击的“停止扫描”按钮。
- 停止后保留已经成功加入的图片；后续仍可再次扫描。
- 单个文件读取失败不应中断整个扫描，并以警告计数体现。

#### 待压缩列表

- 主页面筛选列表仅代表当前待压缩列表，不再代表某个原图目录的完整扫描结果。
- 列表支持缩略图、文件名、来源位置、格式、尺寸、原始大小、状态、搜索、筛选和排序。
- 支持单项移除、批量移除和清空；正在排队或压缩的项不可移除。
- 支持选择单张、多张或全部筛选结果开始压缩。
- 自动压缩关闭时，新加入且处于待处理状态的图片默认选中，用户可在开始压缩前调整选择；失败项和已压缩项不因重新导入而自动选中。
- 应用每次启动时列表为空，不缓存或恢复上一次列表。

#### 导入后自动压缩

- 顶部提供“自动压缩”开关，默认关闭并持久化用户选择。
- 开启后，只对用户主动拖入或扫描过程中随后新识别且状态为 `pending` 的图片生效。
- 每识别一张图片立即创建一个单图任务，不等待本次扫描结束。
- 扫描途中开关变化只影响变化后识别的图片；关闭开关不取消已经排队或运行的任务。
- 自动任务创建失败时不影响扫描，图片保持待压缩和选中状态。
- 自动压缩不包含后台目录监听、任务恢复或失败自动重试。

#### 保存位置

- 开始压缩不以手动选择目标文件夹为前置条件。
- 桌面版首次启动默认使用 macOS 系统“下载”目录，用户也可以选择自定义目录。
- 用户可在主页面保存位置栏修改或恢复默认目录，入口保持明显且无需进入设置弹窗。
- 未自定义目录时，当前应用会话第一次创建压缩任务时，在下载目录下创建 `图片压缩_YYYY-MM-DD_HH-mm-ss` 文件夹。
- 当前应用打开期间的手动和自动任务共用该目录；重新打开应用后创建新的时间目录。
- 用户指定自定义目录后，结果直接写入该目录，不创建时间子目录。
- 时间目录重名时添加数字后缀，不能覆盖已有目录。
- 同一批次内保留可识别的相对结构；不同来源出现重名时自动添加后缀。
- 首个任务创建失败时应删除刚创建、仍为空且未被其他任务引用的会话目录。
- 压缩完成后提供打开批次目录的入口。

#### 压缩与错误

- 压缩前必须配置并验证 TinyPNG API Key。
- 显示 TinyPNG 本月已用、总量、剩余量、更新时间和异常状态。
- 并发数可配置为 1 至 5；不能超过明确可用的剩余额度。
- 单张失败后立即保留失败状态和可理解的错误，不自动重试。
- 每个失败项单独提供“重新压缩”按钮；只有用户点击后才创建一次新的压缩尝试。
- 额度耗尽或 Key 无效时，尚未开始的同批项目标记失败，不进入等待恢复状态。
- 批次允许成功、失败和取消并存；部分失败不回滚已完成结果。
- 关闭应用时，排队项取消，进行中的请求中止；下次启动不恢复。

#### 安全与桌面能力

- 本机服务仅监听 `127.0.0.1`，写操作使用本地会话令牌并校验来源。
- Electron 渲染进程保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`。
- 拖入文件的真实路径只通过受限 preload 能力取得，不向页面暴露通用 Node API。
- API Key 使用 macOS `safeStorage` 加密保存，完整值不返回页面、不写日志。
- 原图只读；结果采用临时文件、内容校验和原子提交。
- 桌面应用保持单实例，并在启动失败或退出时完整关闭服务和数据库。

#### 验收与测试

- 类型检查、Lint、单元/集成测试、生产构建和 Web E2E 全部通过。
- 自动化测试不得调用真实 TinyPNG，不得消耗真实额度。
- 测试和打包默认离线；本机缺少所需 Electron ZIP 时明确失败，禁止自动下载。
- 固定测试区缓存 Electron 运行时、测试图片和 Node/Electron 两套原生模块 ABI。
- 所有测试命令结束后恢复默认 Node ABI，不影响后续开发命令。

### 3.2 P1：体验与稳健性

- 大目录扫描的批量入库、背压和更细的进度反馈。
- 拖入目录、混合拖入文件与目录、扫描冲突的交互完善。
- 待压缩列表的虚拟化、缩略图缓存上限和磁盘清理策略。
- 更完整的无障碍键盘操作、错误定位和批量失败处理入口。
- 自定义会话目录名称、压缩前保存位置快捷切换和目录结构策略。
- 真实打包应用的自动化启动冒烟、签名与 arm64 原生模块检查。

P1 仍维持会话式列表、手动失败重压和默认下载目录，不重新引入恢复语义。

### 3.3 P2：后续扩展

- Developer ID 签名、Apple 公证和正式更新渠道。
- Windows 与 Linux 的凭据存储、目录选择和安装包。
- 可替换的本地压缩引擎或其他压缩服务。
- 质量参数、格式转换、缩放、裁剪及元数据策略。
- 多工作区或团队能力，但必须重新评估隐私、权限和数据模型。

## 4. 明确不做

以下能力不属于 P0、P1、P2 的既定交付，除非后续重新立项：

- 设置固定原图根目录。
- 后台监听目录或未经过用户主动导入的无人值守压缩。
- 失败自动重试。
- 历史压缩批次记录页面。
- 恢复上一次未完成任务。
- 关闭应用后保留待压缩列表。
- 定时任务或无人值守压缩。

契约、数据库业务状态和页面文案不得出现 `paused`、`awaiting_resume`、`awaiting_quota` 等等待恢复状态。

## 5. 核心验收场景

1. 全新启动时无需选择原图目录，主列表为空，可直接拖入图片。
2. 扫描大目录时能看到实时状态并停止；已扫描图片继续保留。
3. 从不同目录加入同名图片时都能进入列表，压缩结果不互相覆盖。
4. 未指定保存位置时，结果写入“下载/图片压缩_开始时间”。
5. 删除待压缩项后，该图片不进入随后创建的任务。
6. 模拟单张网络失败时只调用 TinyPNG 一次；点击该项“重新压缩”后才再次调用。
7. 模拟额度耗尽时，剩余排队项全部失败且不会在额度刷新后自动继续。
8. 关闭并重新启动后，旧待压缩项、批次和未完成任务均不出现在页面。
9. 在完全断网环境执行测试准备时，只使用已存在且 SHA-256 匹配的 Electron ZIP。
10. 自动压缩关闭时，新识别图片默认选中但不创建任务；开启后逐张创建单图任务。
11. 同一应用会话中的默认输出任务共用一个时间目录，自定义输出则直接写入所选目录。
